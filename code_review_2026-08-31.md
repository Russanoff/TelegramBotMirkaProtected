## 2. Архитектура кода

Стек: **aiogram 3** (Telegram-бот) + **FastAPI** (эндпоинт подписок и вебхук ЮKassa) + **SQLAlchemy (async, SQLite)** + **3x-ui панели** (VLESS/Reality) в 6 странах (Германия, Польша, Латвия, Нидерланды, США, Франция) + оплата картой (ЮKassa), крипто (CryptoPay/aiosend), в разработке — Telegram Stars.

Структура:
- `main.py` — точка входа бота (polling), собирает роутеры aiogram.
- `app/apiux/` — клиент к 3x-ui панелям (`new_client.py:XUI`) и реестр серверов (`servers.py:SERVERS`).
- `app/api_main/subs_endpoint.py` — FastAPI-эндпоинт `/subs/{token}`, отдаёт пользователю vless-ссылки со всех серверов сразу (для приложений Happ/Hiddify).
- `app/api_yookassa/`, `app/api_crypto/`, `app/api_stars/` — интеграции оплаты.
- `app/bot/` — хендлеры, колбэки, меню, тексты бота.
- `app/db/` — модели User, Payment, Subscription (SQLite, файл `database.db`, корректно исключён в `.gitignore`).

Git: репозиторий уже инициализирован, `origin` = `https://github.com/Russanoff/TelegramBotMirkaProtected.git`, ветки `main` и `subs`.

## 3. КРИТИЧНО: бот в текущем виде не запустится

В `app/bot/inline_menu/end_subs_menu.py` (клавиатура шагов оплаты) пропущена запятая между кнопками:

```python
step_one = InlineKeyboardMarkup(inline_keyboard=[
    [InlineKeyboardButton(text="КартаМИР/VISA/СБП...", callback_data="card_pay")],
    [InlineKeyboardButton(text="CryptoBot💵(USDT)", callback_data="usdt_pay")],
    [InlineKeyboardButton(text="TelegramStars⭐", callback_data="stars_pay")]      # <- нет запятой
    [InlineKeyboardButton(text="↩️Назад", callback_data="back_main_menu")]
])
```

Из-за отсутствия запятой Python читает это не как два элемента списка, а как **обращение по индексу**: `[кнопка3][кнопка4]`. Проверено локально — это гарантированно даёт `TypeError: list indices must be integers or slices, not InlineKeyboardButton` в момент импорта модуля.

Этот файл импортируется в `main_menu_callbacks.py`, который импортируется в `main.py` при старте. То есть **бот не запускается вообще**, пока это не исправлено — падает на старте с TypeError. Похоже, это случилось при добавлении кнопки Stars (карточка "Оплата звёздами TG" в статусе "В работе").

Заодно: кнопка `stars_pay` ведёт в никуда — обработчика `F.data == "stars_pay"` нигде нет (в `pay_callbacks.py` обрабатываются только суффиксы `_access` и `_accesscry`), а `app/api_stars/stars_pay.py` — просто заглушка из одних импортов без функций, и никуда не подключена (роутер Stars не зарегистрирован в `main.py`). Фича Stars на данный момент — черновик, не работает даже после фикса запятой.

**Фикс — одна строка** (добавить запятую после `stars_pay`). Могу поправить сразу, если скажете.

## 4. Безопасность — требует внимания до передачи репозитория

1. **Реальные пароль и логин от панели 3x-ui (Франция) в открытом виде в коде**, файл `app/apiux/testconnect.py`:
   ```python
   USERNAME = "adminser"
   PASSWORD = "Miroslava_101113"
   BASE = "https://france.mirkaprotected.ru:3354/KO2KCUI6V1HdkLGpGP"  # секретный путь панели
   ```
   Этот файл **не** в `.gitignore` (там только `.env`, `*.db`, `venv`, `__pycache__`). Если он хоть раз попадал в коммит — пароль и секретный URL панели уже в истории git, и удаление файла сейчас это не исправит (нужна перезапись истории + смена пароля). Нужно проверить `git log -- app/apiux/testconnect.py` и, если файл коммитился, сменить пароль панели и переписать историю (или просто сменить пароль — так надёжнее и проще).

2. **Один и тот же логин/пароль администратора (`ADMIN`/`PASSWORD` из `.env`) используется для всех 6 панелей 3x-ui** (`servers.py`). Утечка одной панели = доступ ко всем серверам.

3. **`verify=False`** в HTTP-клиенте к панелям (`new_client.py`) — проверка TLS-сертификата отключена для всех соединений с панелями. Если это самоподписанные сертификаты — окей, но тогда лучше явно доверять конкретному сертификату, а не отключать проверку целиком (риск MITM на удалённых серверах).

4. Отдельный файл `secret_key (1).txt` лежит рядом с проектом (вне репозитория, в `~/Desktop/BotTG/`) — не трогал его, просто фиксирую, что он существует.

## 5. Другие замечания по коду (не критично, но стоит поправить)

- **Утечка соединений**: `XUI.__init__` создаёт `httpx.AsyncClient` на каждый вызов, но в `subs_endpoint.py` (эндпоинт `/subs/{token}`) и в `callbacks_vpn_menu.py:get_link` клиент **никогда не закрывается** (`xui.close()` не вызывается) — в отличие от `crypto.py`/`fastapi_conn.py`, где `close()` есть. При активном использовании `/subs/{token}` это будет постепенно накапливать открытые соединения.
- **`subs_endpoint.py`** при каждом обращении пользователя опрашивает **все 6 панелей заново** без обработки ошибок — если хотя бы одна панель недоступна, весь эндпоинт падает и пользователь не получит ни одной ссылки, включая рабочие сервера.
- **Возможный краш в `profile()`** (`main_menu_callbacks.py`): если у пользователя есть `ends_at` (например, включён триал), но ещё нет ни одного `Payment` со статусом `succeeded`, `payment` будет `None`, а код обращается к `payment.amount` → `AttributeError`.
- Мёртвый код: в `pay_callbacks.py` дважды делается `select(Payment).where(Payment.user_id == None)`, результат нигде не используется.
- Пустой файл `app/api_crypto/crypto_pay.py` (0 байт) — нигде не импортируется, похоже на черновик, можно удалить.
- Много голых `except: pass` — если что-то пойдёт не так, ошибка молча проглатывается без лога (кроме crypto.py/fastapi_conn.py, там хотя бы `print`).
- В `reminder.py` всем пользователям с истекающей завтра подпиской рассылаются **одинаковые захардкоженные логин/пароль** от временных прокси (`john/carter`, `piter/parker`) — если это осознанное решение (общий бесплатный прокси), то ок, просто фиксирую как техдолг (не параметризовано, хранится в коде текстом).
