# MirkaProtected: памятка по эксплуатации

Секретов здесь нет: логины, пароли и токены лежат в `.env` на сервере (в git не попадает).

## 1. Как всё устроено

| Часть | Где | Что делает |
|---|---|---|
| Бот | `bot.service` → `main.py` | Telegram-бот (aiogram), сверка платежей, напоминания, админ-меню |
| API | `api.service` → uvicorn `app.api_yookassa.fastapi_conn:app`, порт 8000 | вебхук ЮKassa, подписки `/subs/<токен>`, лендинг триала |
| nginx | `/etc/nginx/sites-enabled/bot`, `/etc/nginx/conf.d/trial.conf` | `yookassa.` и `subs.` → API; `trial.` пропускает только `/`, `/static/`, `/api/trial`, `/t/`, `robots.txt`, `sitemap.xml` |
| База | `database.db` (SQLite) в папке проекта | и бот, и API работают с одним файлом |
| Узлы | `SERVERS` в `app/apiux/servers.py` | отдельная панель 3x-ui на каждый узел; логин и пароль общие (`.env`) |

Сервер бота: `31.56.48.61` (HostVDS, Bot_TG), проект в `/root/TelegramBotMirkaProtected`, вход `root` по ключу `~/.ssh/mirka_trial`.
Сервер бота не VPN-узел: на нём только бот, API и лендинг.

Как клиенты попадают на узлы: бот собирает ссылки из панелей при каждом обновлении подписки. Если для пользователя на узле ещё нет клиента, бот создаёт его сам (срок берётся из базы). Поэтому **при добавлении узла переносить клиентов не нужно**.

## 2. Админ-меню и команды

Одно меню: `/admin` (кнопка «/» у поля ввода показывает команды только админу).

- 📊 Статистика · 💳 Платежи (+ «Сверить с ЮKassa сейчас») · 🌍 Узлы (карточка: перенастроить конфиги, сменить SNI) · 📣 Рассылки (вернуть ушедших; сообщение всем с подтверждением) · 👥 Клиенты (поиск по ID, продление вручную на 7/30 дней без реферального бонуса) · 🧹 Сервис (удалить записи про удалённые узлы, версия кода).
- Команды: `/winback`, `/fixnode УЗЕЛ [домен]` (ротация Service Name, uTLS, Short IDs, ключей; опционально новый SNI), `/fixsni УЗЕЛ домен|auto`, `/refstats`, `/user_count`, `/postman текст` (теперь тоже с предпросмотром и подтверждением), `/cancel` выходит из режима ввода.
- Перед любой записью в панель делается бэкап (`backups/reality/`, права 600, в git не попадает), после записи проверяются клиенты, при расхождении откат.

## 3. Уведомления админу в Telegram

- 🆕 новый клиент (ID, имя, откуда пришёл) · 🚨 любая ошибка в боте или API (тип, файл:строка, кто и что нажимал) · 🔴 узел не ответил при выдаче подписки · ℹ️ платёж не оплачен / ⚠️ оплачен, но вебхук не дошёл (продлено сверкой).
- Одинаковые события группируются (не чаще раза в 10 минут), общий потолок 30 за 10 минут; если что-то отброшено, следующее уведомление об этом скажет.

## 4. Как выкатывать

0. **Перед SSH проверьте VPN на Маке:** `route -n get 31.56.48.61` и `curl api.ipify.org`. Если трафик идёт через узел, который сейчас тормозит, SSH и сайт будут зависать (так уже было).
1. Тесты зелёные, ветка слита в `main`, `git push`.
2. На сервере: копия базы `sqlite3` `.backup` в `/root/backups/`, затем `git pull --ff-only`, `python -m py_compile` по всем `.py`.
3. Перезапуск: сначала `bot.service` (до `Run polling` ~15 с), затем `api.service` (**~20–35 с без вебхука ЮKassa и подписок**; ЮKassa повторяет недоставленные уведомления).
4. Проверка: `systemctl is-active nginx api.service bot.service`, `journalctl -u bot.service -u api.service --since "-3min"`, `curl https://trial.mirkaprotected.ru/`, один триал и ссылки `/t/<токен>` (потом удалить строку из `web_trials`).
5. Изменение nginx: копия конфига в `/root/backups/`, `nginx -t`, только потом `systemctl reload nginx`.

Напоминания об окончании подписки теперь не повторяются при перезапуске (метка `users.last_reminder`).

## 5. Откат

- Код: `git log --oneline -5` на сервере, `git checkout <коммит>`, перезапуск сервисов; потом `git checkout main`. Новые колонки в базе безвредны для старого кода, восстанавливать базу для отката кода не нужно.
- База (только при порче данных): остановить `bot.service` и `api.service`, скопировать нужный файл из `/root/backups/` на `database.db`, запустить.
- Узел: бэкап прежних настроек лежит в `backups/reality/`; вернуть SNI можно командой `/fixsni УЗЕЛ прежний_домен` (она указана в отчёте).

## 6. Диагностика

- Журналы: `journalctl -u bot.service -f`, `journalctl -u api.service -f`. SQL в журнал не пишется; для отладки задайте `SQL_ECHO=1` в окружении сервиса.
- Доступность узла **из России** (то, что видят клиенты): TCP-проверка на check-host.net (`/check-tcp?host=IP:443` с точками ru1, ru2, ru3). Узел, недоступный из Москвы, но живой из-за рубежа, заблокирован по IP (так было с Францией): ключи и SNI не помогут, нужен другой IP.
- Узел отвечает по TCP, но клиентов онлайн 0: проверяйте протокол (SNI/uTLS/Service Name) и обновили ли клиенты подписку (приложение обновляет её раз в 3 часа). Логи самого xray через API панели недоступны, нужен SSH на узел.
- Оплата: `/admin → Платежи`; платёж в ожидании старше 10 минут сверка проверяет сама каждые 5 минут (последние 3 дня).

## 7. Как добавить узел

1. Сервер в другой подсети или у другого хостера (блокируют целыми диапазонами). Адрес сначала проверьте из России (см. выше). При создании в HostVDS выберите SSH-ключ «VPN-bot».
2. Установите 3x-ui с тем же логином и паролем, что у остальных панелей. Создайте inbound vless / grpc / reality на 443, `remark` = имя узла, SNI из списка `/fixsni` (проверен на TLS 1.3 + HTTP/2 и доступность из РФ).
3. Добавьте блок в `SERVERS` (`name`, `panel_url`, `remark`, `sub_base`, `host`), заведите DNS A-запись для `host`.
4. Тесты, выкатка. Клиенты создадутся сами при ближайшем обновлении подписки.
5. Удаление узла: убрать блок из `SERVERS`, затем `/admin → Сервис → Записи про удалённые узлы`.

## 8. Известные ограничения

- На сервере 1 ГБ памяти и нет swap: тяжёлые задачи запускайте не там.
- Выдача подписки опрашивает узлы по очереди (около 2 с на 5 узлов); недоступная панель ждёт не дольше 8 с.
- Платежи Stars и CryptoBot сверкой не охвачены (только ЮKassa).
- Триал: 48 часов на всех узлах, не больше 2 на один IP за сутки.

## 9. Проверка узлов настоящим клиентом Xray

Панель и открытый порт не показывают, работает ли сам туннель. `tools/node_e2e_probe.py` создаёт на каждой панели временного клиента `PROBE_…`, запускает клиент Xray на сервере бота и гонит запрос через узел с каждым отпечатком uTLS; в конце клиент удаляется. Инструкция по скачиванию Xray-core (с проверкой SHA-256) в шапке скрипта.
Что выяснено этим способом (2026-10-15, xray 25.12.8, транспорт gRPC + Reality): на всех 5 узлах проходят отпечатки `chrome`, `firefox`, `safari`, `ios`, `edge`, `random`; **`android` не проходит нигде**. Домен без HTTP/2 (например `apple.com` без `www`) в SNI даёт ошибку рукопожатия TLS. Тест идёт из Франции и блокировки провайдеров РФ не показывает.
